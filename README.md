# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности данных: товар и покупатель.

### Тип способа оплаты

Для описания доступных способов оплаты используется тип `TPayment`.

```ts
type TPayment = 'online' | 'cash' | '';
```
Значение:
`online`— оплата онлайн;
`cash`  — оплата при получении;
`''` пустая строка — способ оплаты ещё не выбран.

### Интерфейс товара `IProduct`

Интерфейс `IProduct` описывает товар, доступный в каталоге приложения.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```
Поля интерфейса:

`id: string` — уникальный идентификатор товара;
`description: string` — описание товара;
`image: string` — ссылка на изображение товара;
`title: string` — название товара;
`category: string` — категория товара;
`price: number | null` — стоимость товара. Значение `null` используется для товара, который нельзя приобрести за определённую стоимость.


### Интерфейс покупателя `IBuyer`

Интерфейс `IBuyer` описывает данные, которые пользователь должен указать при оформлении заказа.

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Поля интерфейса:

`payment: TPayment` — выбранный способ оплаты;
`email: string` — электронная почта покупателя;
`phone: string` — номер телефона покупателя;
`address: string` — адрес доставки.

### Тип ошибок валидации покупателя

Для хранения ошибок валидации данных покупателя используется тип, свойства которого соответствуют полям интерфейса `IBuyer`.

```ts
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

Каждое свойство объекта содержит текст ошибки соответствующего поля. Если поле заполнено корректно, его свойство в объекте ошибок отсутствует.

Пример:

```ts
{
  payment: 'Не выбран способ оплаты',
  email: 'Укажите email'
}
```

Такой объект означает, что поля `payment` и `email` заполнены некорректно, а поля `phone` и `address` прошли проверку.

## Модели данных

Для хранения данных приложения и работы с ними используются три модели:

`ProductCatalog` — каталог товаров;
`Basket` — корзина покупателя;
`Buyer` — данные покупателя.

Каждая модель отвечает только за свою часть состояния приложения и не занимается отображением данных в интерфейсе.

### Класс `ProductCatalog`

Класс `ProductCatalog` отвечает за хранение товаров, полученных с сервера, а также за хранение товара, выбранного пользователем для подробного просмотра.

#### Конструктор

```ts
constructor()
```

Конструктор не принимает параметров. При создании экземпляра каталог товаров пуст, а выбранный товар отсутствует.

#### Поля

```ts
private products: IProduct[];
```

Массив всех товаров, доступных в приложении.

Начальное значение — пустой массив.

```ts
private selectedProduct: IProduct | null;
```

Товар, выбранный пользователем для подробного отображения.

Если товар ещё не выбран, поле содержит `null`.

#### Методы

##### `setProducts`

```ts
setProducts(products: IProduct[]): void
```

Сохраняет переданный массив товаров в модели каталога.

Параметры:

`products: IProduct[]` — массив товаров.

Метод ничего не возвращает.

##### `getProducts`

```ts
getProducts(): IProduct[]
```

Возвращает массив всех товаров, сохранённых в каталоге.

Возвращаемое значение:

`IProduct[]` — массив товаров.

##### `getProductById`

```ts
getProductById(id: string): IProduct | undefined
```

Находит товар по его уникальному идентификатору.

Параметры:

`id: string` — идентификатор товара.

Возвращаемое значение:

`IProduct` — найденный товар;
`undefined` — если товар с таким идентификатором отсутствует.

##### `setSelectedProduct`

```ts
setSelectedProduct(product: IProduct): void
```

Сохраняет товар, выбранный пользователем для подробного отображения.

Параметры:

`product: IProduct` — выбранный товар.

Метод ничего не возвращает.

##### `getSelectedProduct`

```ts
getSelectedProduct(): IProduct | null
```

Возвращает товар, выбранный для подробного отображения.

Возвращаемое значение:

`IProduct` — выбранный товар;
`null` — если товар ещё не выбран.

### Класс `Basket`

Класс `Basket` отвечает за хранение товаров, которые пользователь выбрал для покупки, а также за операции с корзиной: добавление, удаление, очистку, подсчёт количества товаров и общей стоимости.

#### Конструктор

```ts
constructor()
```

Конструктор не принимает параметров.

При создании экземпляра корзина содержит пустой массив товаров.

#### Поля

```ts
private products: IProduct[];
```

Массив товаров, добавленных пользователем в корзину.

Начальное значение — пустой массив.

#### Методы

##### `getProducts`

```ts
getProducts(): IProduct[]
```

Возвращает массив товаров, находящихся в корзине.

Возвращаемое значение:

`IProduct[]` — массив товаров корзины.

##### `addProduct`

```ts
addProduct(product: IProduct): void
```

Добавляет товар в корзину.

Параметры:

`product: IProduct` — товар, который необходимо добавить.

Метод ничего не возвращает.

##### `removeProduct`

```ts
removeProduct(product: IProduct): void
```

Удаляет переданный товар из корзины.

Параметры:

`product: IProduct` — товар, который необходимо удалить.

Метод ничего не возвращает.

##### `clear`

```ts
clear(): void
```

Полностью очищает корзину.

После выполнения метода массив товаров становится пустым.

Метод ничего не возвращает.

##### `getTotalPrice`

```ts
getTotalPrice(): number
```

Вычисляет и возвращает общую стоимость всех товаров, находящихся в корзине.

Возвращаемое значение:

`number` — сумма стоимости товаров.

Товары со значением `price: null` не должны увеличивать общую стоимость.

##### `getProductsCount`

```ts
getProductsCount(): number
```

Возвращает количество товаров в корзине.

Возвращаемое значение:

`number` — количество товаров.

##### `hasProduct`

```ts
hasProduct(id: string): boolean
```

Проверяет наличие товара в корзине по его идентификатору.

Параметры:

`id: string` — идентификатор товара.

Возвращаемое значение:

`true` — товар находится в корзине;
`false` — товара в корзине нет.

### Класс `Buyer`

Класс `Buyer` отвечает за хранение данных покупателя, их изменение, получение, очистку и валидацию перед оформлением заказа.

#### Конструктор

```ts
constructor()
```

Конструктор не принимает параметров.

При создании экземпляра все данные покупателя имеют пустые значения.

Начальное состояние модели:

```ts
{
  payment: '',
  email: '',
  phone: '',
  address: ''
}
```

#### Поля

```ts
private payment: TPayment;
```

Хранит выбранный способ оплаты.

Начальное значение — пустая строка.

```ts
private email: string;
```

Хранит электронную почту покупателя.

Начальное значение — пустая строка.

```ts
private phone: string;
```

Хранит номер телефона покупателя.

Начальное значение — пустая строка.

```ts
private address: string;
```

Хранит адрес доставки.

Начальное значение — пустая строка.

#### Методы

##### `setData`

```ts
setData(data: Partial<IBuyer>): void
```

Сохраняет переданные данные покупателя.

Использование `Partial<IBuyer>` позволяет передавать только часть данных и изменять отдельное поле, не удаляя значения остальных полей.

Например:

```ts
buyer.setData({
  address: 'Москва, ул. Пушкина, д. 4'
});
```

В этом случае изменится только адрес, а ранее сохранённые `payment`, `email` и `phone` останутся без изменений.

Параметры:

`data: Partial<IBuyer>` — объект с одним или несколькими полями покупателя.

Метод ничего не возвращает.

##### `getData`

```ts
getData(): IBuyer
```

Возвращает все сохранённые данные покупателя.

Возвращаемое значение:

`IBuyer` — объект с данными покупателя.


##### `clear`

```ts
clear(): void
```

Очищает все данные покупателя и возвращает модель в начальное состояние.

После выполнения метода:

```ts
{
  payment: '',
  email: '',
  phone: '',
  address: ''
}
```

Метод ничего не возвращает.


##### `validate`

```ts
validate(): TBuyerErrors
```

Проверяет данные покупателя.

Каждое обязательное поле считается валидным, если оно не пустое.

Метод возвращает объект с ошибками. Ключ объекта соответствует полю покупателя, а значение содержит текст ошибки.

Если поле заполнено корректно, соответствующее свойство в объекте отсутствует.

Возвращаемое значение:

`TBuyerErrors` — объект с ошибками валидации.

Например:

```ts
{
  payment: 'Не выбран способ оплаты',
  address: 'Укажите адрес доставки'
}
```

Если все данные заполнены корректно, метод возвращает пустой объект:

```ts
{}
```

Таким образом, модель позволяет определить как общую валидность данных покупателя, так и ошибку каждого отдельного поля.

##### Слой коммуникаций

Отвечает за взаимодействие приложения с API сервера Web-Larёк. Используется для получения каталога товаров с сервера и отправки данных оформленного заказа.

Для работы с HTTP-запросами используется базовый класс `Api`, предоставленный в стартере проекта.

### Класс `WebLarekApi`

Отвечает за выполнение запросов, относящихся непосредственно к интернет-магазину.


#### Конструктор

```ts
constructor(api: IApi)
```

Принимает:

`api: IApi` — объект, который отдает методы для выполнения GET- и POST-запросов.

Переданный объект используем для выполнения запросов к серверу.

#### Поля класса

`api: IApi` — хранит объект коммуникационного слоя, который предоставляет методы `get` и `post` для выполнения HTTP-запросов.

#### Методы класса

`getProducts(): Promise<IProductsResponse>` — делает GET-запрос на эндпоинт `/product/`.

Возвращает промис с объектом типа `IProductsResponse`.

Объект ответа содержит:

`total: number` — количество товаров;
`items: IProduct[]` — массив товаров.

`createOrder(order: IOrder): Promise<IOrderResult>` — выполняет POST-запрос на эндпоинт `/order/`.

Принимает:

`order: IOrder` — данные оформляемого заказа.

Объект заказа содержит данные покупателя, общую стоимость заказа и массив идентификаторов выбранных товаров.

Возвращает промис с объектом типа `IOrderResult`.

Объект содержит:

`id: string` — идентификатор созданного заказа;
`total: number` — итоговая стоимость заказа.

### Типы данных коммуникационного слоя

Для описания ответа сервера с каталогом используется интерфейс:

```ts
export interface IProductsResponse {
    total: number;
    items: IProduct[];
}
```

Интерфейс не описывает товар повторно, а использует уже существующий интерфейс `IProduct`.

Для описания данных заказа используется интерфейс:

```ts
export interface IOrder extends IBuyer {
    total: number;
    items: string[];
}
```

Интерфейс `IOrder` расширяет `IBuyer`, поэтому наследует поля:

`payment`;
`email`;
`phone`;
`address`.

Дополнительно содержит:

`total: number` — общую стоимость заказа;
`items: string[]` — массив идентификаторов товаров.

Для описания ответа сервера после успешного оформления заказа используется интерфейс:

```ts
export interface IOrderResult {
    id: string;
    total: number;
}
```

Класс `WebLarekApi` 
- не хранит данные приложения и не отвечает за их отображение; 
- его задача — обмен данными между приложением и сервером.
